# Note Taking Guidelines for DSA Vault

Whenever creating, modifying, or updating notes in this vault (`DSA`), follow these rules automatically:

## 1. Language & Style Standards
- **Formal Definitions**: Always write formal technical and academic definitions in proper, clear, and precise **English**.
- **Explanations & Logic**: Write conceptual breakdowns, "Explain like I'm 5" sections, analogies, step-by-step logic, approach descriptions, code comments, and key takeaways in **Hinglish** (conversational Hindi in Latin script mixed with standard English technical terms).

## 2. Note Structure & Formatting
- **Obsidian Tags**: Include relevant Obsidian tags at the top of the file (e.g., `#dsa #java #array #sorting #linkedlist`).
- **Wikilinks**: Maintain interconnected notes using Obsidian wikilinks (e.g., `[[Arrays]]`, `[[Singly Linked List (SLL)]]`).
- **LaTeX Notation**: Format all time and space complexities using LaTeX math syntax (e.g., `$O(1)$`, `$O(N)$`, `$O(N \log N)$`).
- **Code Blocks**: Provide complete Java implementations with proper syntax highlighting and helpful Hinglish comments.

## 3. Standard Layout for Concept Notes
1. `# [Topic Title]`
2. Tags (e.g., `#dsa #java #array`)
3. `## Formal Definition` *(Strictly in Proper English)*
4. `## "Explain like I'm 5" (Aasan Bhasha Mein)` *(In Hinglish)*
5. `## Real-Life Analogy` *(In Hinglish)*
6. `## How it Works (Step-by-Step Logic)` *(In Hinglish)*
7. `## Code (Java)` *(Java with Hinglish comments)*
8. `## Complexity Analysis (Interview Perspective)` *(Table & Hinglish explanation)*
9. `## Kab Use Karein? (When to Use)` *(In Hinglish)*
10. `## Pros & Cons` *(In Hinglish)*

## 4. Standard Layout for Problem Notes
1. `# [Problem Title]`
2. Tags & Concept Wikilink (e.g., `> **Concept:** [[Arrays]]`)
3. `## Problem Statement` *(In Proper English)*
4. `## Approach (Tarika)` *(In Hinglish)*
5. `## Code (Java)` *(Java with Hinglish comments)*
6. `## Output`
7. `## Time & Space Complexity`
8. `## Key Points (Khaas Baatein)` *(In Hinglish)*
